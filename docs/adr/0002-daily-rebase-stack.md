# Upstream sync stays a daily rebase stack

`otterware` keeps Otter Code's sync model from `OTTER.md`: `upstream-base` marks the T3 Code
commit, Otter's work sits on top as feature commits plus one squash commit per past sync, and
publishing a sync force-pushes `main` with leases. Work between syncs lands on `main` through PRs.

We chose this over merging upstream because it keeps the fork's diff readable as a short stack,
and the process is already known and scripted.

Consequence: every edit to an upstream-owned file is a potential conflict on every sync, so
modules live in Otter-owned folders and reach the host only through a small, stable set of
extension seams. The number of upstream files touched is a budget to be tracked, not a free
choice. Generated shared files (`pnpm-lock.yaml`) are regenerated by the adaptation script
rather than resolved by hand, and auto-merge (ADR 0014) is paused while a sync is published so
the force-with-lease push does not race merges (the old `otterware` branch of `otter-code` touches 126).
